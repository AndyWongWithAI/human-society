# 审查评分卡 (Review Rubric Card)

> 用途:独立对抗审查者的**唯一校准来源**。读这一页即可,**不必去读其它参照推论**(那是 670 行的浪费)。
> 立场:默认怀疑,宁可错杀不放水。本体系最高原则"方法论 > 任何单条推论"——毙掉弱推论是加分。
> 作者侧对应清单见 `author-checklist.md`(同一批红旗)。

## 你的任务

对一条待审推论(`DED-NNN`)做 Rule B 独立对抗审查(作者≠审查者,全新上下文)。**尽最大努力打穿它**,给硬裁决。

## verified 的定义(三条同时满足才算)

1. **无 required 级缺陷**(见下红旗;required = 不修则推论不成立/不可证伪/事实错)。
2. **你【亲自做过反例猎捕】,且没猎到 scope 内的活反例**(只猎到被消化/支持的案例)。—— 这条是硬门:任何判 verified 的轮次,必须在记录里留下反例猎捕过程。没猎过不许判 verified。
3. **未重蹈 DED-004(不可证伪循环)/ DED-007(测量轴焊死)**。

达不到 → `needs_revision`(可修)或 `rejected`(核心塌了、无法靠改措辞救活)。

## 通用红旗清单(16 条,逐条给结论:命中/未命中/攻不穿)

> 本清单是通用红旗的**唯一定义**(canonical definition)。L4 评分卡(`l4-review-rubric.md`)继承这 11 条,只追加 L4 专属红旗(第 12–18 条),不重复定义。

1. **brick=conclusion** — 非平凡内核是否原文/近义已在某承重砖里?砖是否"专为这条推论窄化"?
2. **逐格判空** — 核心的空格预测是真经验主张还是同义反复?被砖平凡强制吗?
3. **测量轴正交(DED-007 死因)** — 自变量与被预测量是否异源正交?有无隐藏焊点(自变量偷用结果测,如分母用"实际获授者")?
4. **射程/排除钩子独立于结果(DED-005)** — excluded_outcomes 按可事前测的渠道划,还是事后按结果开脱?
5. **分类判据档位匹配(DED-006)** — 分档数是否匹配被救对象(连续量别用二分)?
6. **anti-talisman 真兑现** — 判定前件不由结果反推;且至少一个承重锚【真的独立测出】驱动量(非嘴上说)?
7. **现实锚事实核查(DED-007 死因)** — 历史/经验锚有无事实错或过度解读?
8. **条件是下定义还是做预测** — 关键条件是必然为真的定义,还是可证伪的预测?
9. **枚举穷尽 + species 按判据定义(DED-008)** — 若声称"N 类可枚举":每类是否按【伞级判据本身】定义(而非相关但不等价的表征)?**主动猎第 N+1 类**——猎到=required 新洞。
10. **primary_suspect 指对 + 平凡化检查** — 文件自认最弱腿准不准?有无更致命软肋它没认?上位/泛化后有没有被稀释成相邻理论的常识(如委托-代理"需问责")?
11. **口径完整注册 + 歧义反向裁决(L4-009 判例)** — 阈值/判据是否连同分子、分母、测量口径【一次性注册】?发现"只有数字没有口径"→ 直接标记 required。若某个边界案例的裁决依赖【事后】口径选择(口径在反例出现后才定死,且定死方向恰好救推论),该边界案例一律按【不利于推论】方向裁,对应闸门不得计为守住——哪怕作者的机制理由可辩护。为什么:事后选择的方向性让"理由的质量"失去证据价值,聪明的作者永远能为救命的分叉编出体面理由;预注册漏洞的成本必须由推论承担,否则等于奖励模糊注册。(判例:L4-009 阈值未注册分母口径,2011 利比亚冻结宽口径过线、窄口径不过线,口径在见反例后才定死为救推论的窄口径。)
12. **数据源同根冒充多源独立** — 声称"多源验证"的经济/统计锚点,引用的多个机构(如 CNBS/WB/IMF)是否共享同一套底层数据源?若同根 → 独立系数 ≤0.1,不得当作多重独立验证。查 `sources/independence-model.yaml` 的 `data_source_origin` 节。(判例:CNBS 工具实证发现 WB/IMF 的中国 GDP 均以 CNBS 国家账户为底层输入,三源一致 ≠ 三源独立——"多源≠独立"是本红旗的核心教训。)
13. **API 可及性冒充认识论独立性** — 作者是否将"能通过 API/MCP 查到"当作"多源独立证据"?工具可靠性(能否调通、是否有限流)是工程信息,不是认识论信息。多路 API 查询若走同一底层数据源,独立票数不应增加。诚实标注:哪些数据源是独立测量链、哪些只是同一数据的不同 API 包装。
14. **反向失败模式缺失(DED-039/047 判例)** — 推论不仅注册了"怎么被证伪",是否也注册了"怎么在相反方向失败"?如"AI代码替代叙事"的反向失败是"AI代码放大叙事"(代码引入后叙事厚度反而增长→Δ叙事>0而非≈0)。若反向模式未被注册而你在审查中发现了它→标记 should(若反向模式的方向恰好与推论的因果主张相反,升级为 required——因为此时需要区分"替代"和"放大"两个互斥的因果方向)。问:驱动量的变化是否可能产生与被预测方向恰好相反的观测结果?若可能且未注册,这就是反向失败模式缺口。
15. **Bootstrap限定缺失(DED-039 判例)** — 涉及新技术介导社会形态的推论(如AI代码协调/算法治理/DAO),是否区分了冷启动阶段 vs 稳态运行阶段?若推论声称"X可替代Y"但所有已知成功案例的冷启动阶段均深度依赖Y,则推论的稳健主张应是"稳态下X可替代Y,冷启动阶段Y仍为必要"。若文件未做此限定而你在反例猎捕中发现了冷启动依赖的证据,标记 should。
16. **验证对象存在性未标注(DED-039 判例)** — 推论的证实条件在当前技术-社会条件下是否可观测?若推论的理想检验对象(如"验证型信任可达的纯代码型协调体")在当前世界中近乎空集,文件是否诚实标注了"推论描述的是理论可能性而非当前实践常态"?若未标注,标记 should——这不影响可证伪性(证伪条件仍然清晰),但影响推论的实证置信度上限。多轮审查反复发现同一"空集"问题是此红旗的强信号。

## 反例猎捕(必做,尤其判 verified 前)

主动构造一个能证伪核心的干净案例(满足 falsifiability(a) 的最强形式)。认真找历史/跨文化实例,别敷衍。三种结果:
- **净杀** → rejected 或 required。
- **被消化/反成支持** → 记录为何(往往反哺一个锚或 species)。
- **揭出别处过度伸张** → 定位到具体预测/判别,列 required/should。

## 裁决语义

- `verified` — 满足上面三条。
- `needs_revision` — 有 required/should 缺陷,但可靠定向修订救活(列最小清单)。
- `rejected` — 核心塌陷(brick=conclusion 无法解、测量轴焊死无法拆、被净杀反例、事实错致命),改措辞救不活。

1. **把完整评审写进** `ADV-REVIEW-NNN` 的 `round_<N>` 块(与既有 round 同构字段:reviewer / verdict / verdict_note / 红旗逐条 / counterexample_hunt / non_recurrence / 若非 verified 的 required_fixes)。只改本轮块,别动别轮。写完跑 `python scripts/validate.py` 确认 YAML 不破(长文本用 `|` 块标量,防中文里的 ASCII 冒号顶飞)。
2. **只向调用方返回紧凑结果**(不复述全文):
   ```
   VERDICT: verified | needs_revision | rejected
   REQUIRED_FIXES: 无 | 1) ... 2) ...(每条一行,≤5条,可操作)
   COUNTEREXAMPLE: 猎捕结果一句话(净杀/被消化/揭出过度伸张)
   ONELINE: 一句话总评
   ```

严格独立。够格 verified 就明说;差一口气就精确指出差在哪。不制造假问题,也不为让作者好过而放水。

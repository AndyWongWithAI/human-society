# L4 审查评分卡 (L4 Review Rubric Card)

> 用途:L4 复合推论的独立对抗审查者**唯一校准来源**。在标准 L3 评分卡基础上增加 L4 专属红旗。
> 立场:默认怀疑，宁可错杀不放水。L4 离地基更远，标准必须比 L3 更严。

## 你的任务

对一条待审 L4 复合推论(`L4-NNN`)做 Rule B 独立对抗审查。**尽最大努力打穿它**，给硬裁决。

## verified 的定义（L4 版——L3 三条 + L4 三条，同时满足）

**L3 标准条件:**
1. **无 required 级缺陷**（标准红旗 + L4 专属红旗）。
2. **你亲自做过反例猎捕**，且没猎到 scope 内的活反例。
3. **未重蹈 DED-004/DED-007**。

**L4 附加条件:**
4. **涌现有效**：必要性（无观众砖）、新颖性（非父推论 AND/OR）、多父逐格判空（至少一个合力格）。
5. **复合非平凡性通过**：逐格判空归属分析确认至少一格需要 ≥2 条父推论合力。
6. **无观众砖**：每条 L3 父推论对结论有不可替代的机制贡献。

达不到 → `needs_revision`（可修）或 `rejected`（核心塌了）。

## 标准红旗清单（逐条给结论，同 L3 评分卡）

1. **brick=conclusion** — L4 的非平凡内核是否已是某条父推论结论的复述？
2. **逐格判空** — 核心的空格预测是真经验主张还是同义反复？
3. **测量轴正交** — 自变量与被预测量是否异源正交？
4. **射程/排除钩子独立于结果** — excluded_outcomes 按可事前测的渠道划？
5. **分类判据档位匹配** — 分档数是否匹配被救对象？
6. **anti-talisman 真兑现** — 判定前件不由结果反推？
7. **现实锚事实核查** — 历史/经验锚有无事实错？
8. **条件是下定义还是做预测** — 关键条件是可证伪的预测？
9. **枚举穷尽 + species 按判据定义** — 声称"N 类可枚举"是否按伞级判据定义？
10. **primary_suspect 指对** — 最弱腿准不准？

## L4 专属红旗（逐条给结论）

11. **观众砖（spectator brick）** — 逐一移除每条 L3 父推论：结论还成立吗？哪条父推论挂着但不出力？
12. **平凡合取（trivial conjunction）** — L4 结论是否只是父推论结论的 AND/OR 拼接？有没有"合起来才推得出"的东西？
13. **涌现缺失** — 多父逐格判空：有没有至少一个格子需要 ≥2 条父推论合力？归零 = 这不是 L4，是 L3 chaining。
14. **弱父前提** — 所有 L3 父推论都是 verified/verified* 吗？有没有 candidate 被用作主前提？
15. **锚点偷窃** — "复合锚点"是否只是重复某条父推论的单机制锚点？换个案例说"A 存在且 B 存在"不算复合锚点。
16. **交互测量缺口** — 复合输出变量能否被测量为"区别于 A 单独 + B 单独"的东西？还是只能测到 A 和 B 各自的结果？
17. **声明类型-证据标准错配** — claim_type 宣称的东西（如 trajectory_prediction）是否有对应的证据（纵向/序列数据）？

## 反例猎捕（必做）

主动构造能证伪 L4 核心的干净案例。L4 的反例猎捕额外要求：
- **不仅要猎"某个父推论不成立"的案例**（那是 L3 的事），要猎"父推论都成立、但交互不产生 L4 预测的结果"的案例。
- 猎到 → 区分：是某条父推论被反例推翻（→ 该父推论的问题，可能连累 L4 天花板），还是交互本身不成立（→ L4 的问题）。

## 裁决语义

- `verified` — 满足 L3 三条 + L4 三条。
- `needs_revision` — 有 required/should 缺陷，可靠定向修订救活（列最小清单）。
- `rejected` — 核心塌陷（平凡合取、观众砖无法消解、净杀反例、测量轴焊死）。

## 你要产出的两件事

1. **把完整评审写进** `L4-composites/reviews/ADV-REVIEW-L4-NNN-*.yaml` 的 `round_<N>` 块。字段:reviewer / verdict / verdict_note / 标准红旗逐条 + L4 专属红旗逐条 / counterexample_hunt / non_recurrence / 若非 verified 的 required_fixes。写完跑 `python scripts/validate.py` 确认 YAML 不破。
2. **只向调用方返回紧凑结果**（不复述全文）:
   ```
   VERDICT: verified | needs_revision | rejected
   REQUIRED_FIXES: 无 | 1) ... 2) ...
   COUNTEREXAMPLE: 猎捕结果一句话
   ONELINE: 一句话总评
   ```

严格独立。L4 离地基更远，标准必须更严——够格 verified 就明说；差一口气就精确指出差在哪。

## P1 执行记录：方案三（核查成本弹性）+ 方案五（DED-033 探测）

### 实测发现：CNBS API 可靠性分层

经过本轮密集调用，四个 CNBS 工具呈现明显的可靠性分层：

| 工具 | 可靠性 | 表现 |
|------|--------|------|
| `cnbs_search` | ⭐⭐⭐⭐ | 前 4-5 轮稳定返回数据，后续触发 redirect（疑似频率限制） |
| `cnbs_batch_search` | ⭐⭐⭐ | 同上，批量模式下更容易触发 redirect |
| `cnbs_fetch_series` | ⭐ | 始终返回 404（API 路由可能已变更） |
| `cnbs_fetch_nodes` | ⭐ | 始终触发 redirect（可能参数格式与服务器期望不匹配） |
| `cnbs_compare` | ⭐⭐ | 返回空结果（关键词匹配过于严格） |
| `cnbs_economic_snapshot` | ⭐ | 返回全 null |
| `ext_world_bank` | ⭐⭐⭐⭐⭐ | 从未失败，数据丰富 |
| `ext_imf` | ⭐⭐⭐⭐⭐ | 从未失败，含 2031 年预测 |
| `ext_global_compare` | ⭐⭐⭐⭐⭐ | 一次调用双源返回 |
| `ext_cn_department` | ⭐ | redirect loop |

**关键结论**：跨源三角验证（方案四）是目前最成熟、最可依赖的路径。CNBS 内部数据（分省/时序）的自动化获取尚未达到生产可用水平。

### 方案三（核查成本弹性）可行性重评估

#### 需要的数据
- 分省能源消费总量 / 单位 GDP 能耗（2005-2025 年面板）
- 分省 SO2/PM 排放量与卫星反演的独立基准对比
- 环保监测站点自动化改造的站点级时间表

#### 当前障碍
1. `cnbs_fetch_nodes("分省年度数据")` 触发 redirect，无法遍历数据树
2. `ext_cn_department("energy")` 同样 redirect
3. 卫星反演数据不在 CNBS 工具链内（需要 NASA MODIS/ESA Sentinel 数据 API）

#### 降级方案（不用 CNBS 也能做）
- 用 `ext_world_bank(indicator="CO2_EMISSIONS", countries=["CHN"])` 获取中国碳排放时序，作为环保数据的一个弱代理
- IMF 预测中缺乏环境维度
- **结论**：方案三的干净执行需要跨越 CNBS 工具链的边界——卫星数据 API（Google Earth Engine、Sentinel Hub）才是这个方案的核心基础设施

#### DED-033 的可检验预测映射

DED-033 声称：社保覆盖面扩大 → 预防性储蓄下降 → 消费释放，但存在信任约束滞后。

从现有数据可以做的是：

1. **宏观时序对照**：储蓄率 (WB) 从 45.1%(2015)→42.7%(2024)，同期社保参保从~8.6亿→~10.8亿。方向一致，但这是单条时序，不能排除第三方因素（经济增速下台阶、人口老龄化、房地产财富效应消退等）。

2. **省际异质性探测（需要分省数据，尚未获取）**：用省际面板做 DiD——社保覆盖率增幅大的省份，储蓄率降幅是否更大？信任约束的代理变量（政府信任度调查、制度质量指标）是否调节该关系？此步依赖 `cnbs_fetch_nodes("分省年度数据")` 的修复。

3. **目前的证据等级**：不足以单独支撑 verified，但足以构成 `supporting, confidence: weak` 的初步锚。升级路径明确：分省面板 + 工具变量（如社保改革的省际推行时点差异）。

## P2/P3：方案二（层级梯度）+ 整体评估

### 方案二（层级梯度）的硬障碍

DED-031 预测(ii) 要求：
- 逐级（全国→省→市→县）GDP 加总偏差测量
- 每层的"利益关联层级数"需按考核文本独立编码

**当前 CNBS 工具限制**：
- `cnbs_fetch_nodes` 无法访问 → 无法获取分省、分市、分县级数据
- `cnbs_search` 中搜索"分省年度数据"返回空（见 memo #1）
- 城市级/县级数据可能根本不在当前 API 覆盖范围内

**结构性评估**：即使 CNBS API 完全可用，方案二也需要大量人工编码（逐层考核文本的"该层是否被该指标考核挂钩"判断）。投入产出比最低——DED-031 已自认 (ii) 是可截肢预测（`secondary_suspect`），即使被推翻也不伤核心机制。

**建议**：方案二降为**远期待办**，不作为本轮验证重点。

## 工具链最终评估：对体系的系统价值

### 已验证的生产级能力
1. **`cnbs_search` + `ext_world_bank` + `ext_imf`** 的组合可以进行高质量的跨源宏观指标对照
2. **World Bank 储蓄率、IMF 政府债务、CPI、失业率** 等数据为 L2 桥接层（特别是 BR-L2-028~031）和 L3 经济推论提供经验锚定
3. 三源的**一致性程度本身**是一个有价值的信息——它告诉我们哪些指标的国际发布流程中失真被压缩，哪些不是

### 需要等待修复后才能解锁的能力
1. 分省面板数据（方案一、方案五的核心）
2. 时序数据批量拉取（`cnbs_fetch_series` 的 404 修复）
3. 能源/环保分省数据（方案三的核心）

### 对体系设计的影响
- DED-031 的验证需要**多源独立基准**而非同源多机构数据——这是本次实测的核心教训
- CNBS 工具链当前更适合做**宏观快照和跨源对照**，而非精细的面板计量
- 真正的独立基准（卫星灯光、用电量、货运量）需要外部 API——考虑接入 Google Earth Engine 或 Sentinel Hub 作为体系的下一个 MCP 工具
